Repository Assessment.txt

What is already here

  • Robot display: pygame/OpenGL manager, terminal, apps, screensavers, camera overlays, touch routing.
  • Remote dashboard: Flask/Jinja, Socket.IO, Bootstrap, five major tabs, responsive mobile navigation, theme CSS.
  • Useful visual assets: VGA, pixel, retro, and mono fonts already live in the repository.
  • Primary constraint: UI code is coupled to generated config and Pi-only audio, camera, network, servo, and OpenGL paths.
  • Maintainability risk: the web UI is concentrated in a 3,885-line stylesheet and a 4,763-line script; device colors/fonts are repeated across modules.
Scope rule: preserve robot behavior first. Visual work begins behind preview fixtures and shared theme primitives; hardware code is not invoked by desktop previews.
Local Preview Protocol.exe

Fast review loop

  1. Run a lightweight pygame preview at the exact robot canvas with simulated sensors and states.
  2. Run a mock Flask server that uses production templates/static assets with deterministic API fixtures.
  3. Capture four review frames: device 480×320, device 800×480, desktop web, mobile web.
  4. Compare, review, then commit one work action only.
  5. Use the Pi only at explicit integration gates, not as the everyday design workstation.
Device preview: .\.venv-ui-preview\Scripts\python.exe .\tools\ui-preview\device_preview.py --app eyes --size 480x320. Use --size 800x480 for the larger display; ESC quits and LEFT/RIGHT switches apps.

Commit Discipline.ini

Rules for every action

  • One workboard row per commit; no opportunistic bundles.
  • Before/after capture for visual changes.
  • State the exact acceptance check in the commit/turn handoff.
  • Do not mix behavior changes with a visual restyle unless the row explicitly requires it.
  • Never exercise servos, shutdown, Wi-Fi mutation, or tunnel actions from preview fixtures.
  • Stop for review at the end of each row or tightly related two-row session.
